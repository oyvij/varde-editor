# Varde stack

Rust, chosen after the spec was complete. The two biggest components of this product are an
**embedded terminal emulator** and a **modal editor with syntax highlighting**. Rust has mature,
reusable crates for both, and Node has almost nothing equivalent.

## Why not Node/ink

Claude Code is built with ink, which shows what ink is good at: a single-pane chat REPL with a
scrolling list of messages, spinners and an input line. Varde is a four-pane IDE with a live shell in
one of them. In Node, `node-pty` spawns the process, but the terminal *model* is the hard part, and
`xterm.js` is tied to the DOM. There is no mature headless cell-grid renderer for a TUI, so you would
be writing an escape-sequence parser by hand.

Go was the runner-up. `bubbletea` is an excellent TUI framework and `vt10x` is a workable terminal
model. Go loses on the editor: tree-sitter needs cgo, and there is no reference implementation of a
modal editor to learn from.

## Crates

| Concern | Crate | Notes |
|---|---|---|
| TUI framework | `ratatui` | Layout, widgets, the four-pane frame |
| Terminal backend | `crossterm` | Cross-platform input/output; also the Kitty keyboard protocol (below) |
| Key encoding | `terminput` + `terminput-crossterm` | A hosted pane forwards every key to its child as the bytes a real terminal would send. `terminput::KeyEvent` is the lossless event type, so nothing is collapsed on the way in, and `Event::encode(&mut buf, Encoding::Xterm)` produces the legacy sequence. Do **not** hand-roll it. Which bytes a modifier combination sends is a solved problem, and its edge cases only show up when someone presses the key. That is what AGENTS.md's "use the crate, don't write the function" is for. `terminput-crossterm` converts the edge's crossterm events, and its default feature already targets crossterm 0.29, the version in the tree. Two small crates from one author, with no second terminal stack behind them |
| Host colours | `terminal-colorsaurus` | Asks the host terminal once, at startup, for its foreground and background (OSC 10/11), so Varde can mix the space dots and indentation guides between them at a strength Varde picks rather than the strength DIM gives. The hard case is detecting a terminal that will not answer without waiting out a timeout, which is why this is a crate and not a `write!`. bat and delta use it. With no answer, Varde falls back to DIM |
| Terminal emulation | `vt100` | **`wezterm-term` is not published to crates.io**; we found that out by trying to add it. `vt100` parses escape sequences into a cell grid and exposes `mouse_protocol_mode()`, which answers R10.5's question: has the running program asked for mouse events? Its `Callbacks::unhandled_csi` matters just as much. It reports every sequence `vt100` does not implement, including the child's queries, instead of dropping it, so Varde can answer them without a parser of its own. `alacritty_terminal` and `termwiz` are the alternatives if more fidelity is needed |
| Pty process | `portable-pty` | Spawns and sizes the user's shell; same family as `wezterm-term` |
| Text buffer | `ropey` | A rope, so edits in the middle of a large file stay cheap |
| Syntax highlighting | `syntect` | **Chosen over tree-sitter.** One crate, no C grammars or highlight queries to wire up, and it returns scopes directly. tree-sitter is still the answer if a *structural* feature arrives (folding, selection by node, smart indent), because those need a parse tree, not scopes |
| Syntax set | `two-face` | `syntect`'s own `load_defaults_nonewlines()` is Sublime's default set: **75 syntaxes, none of them** TypeScript, TSX, Vue, Svelte, Kotlin, Swift, Zig, Dart, TOML, Terraform, Nix, Elixir, protobuf, Dockerfile, GraphQL or SCSS. So Varde's own `config.toml` rendered with no colour while the file tree beside it coloured a `.ts` file by its language. `two-face` packages `bat`'s extended set of **220 syntaxes** as a **prebuilt syntect dump**. It drops into the constructor: same `SyntaxSet` type, no assets directory, no licence audit and no build script. Vendoring `.sublime-syntax` files was rejected because of the build script: parsing 220 YAML grammars costs hundreds of milliseconds on every start, while a dump is `include_bytes!` plus a deserialise. Startup costs nothing because of structure, not the size of that deserialise. The set sits behind an `OnceLock` whose only caller is the edge's per-buffer highlight cache, so opening Varde on a folder never touches it. The one-off measurement, a release build calling both constructors and not a benchmark the suite keeps, was 2.9 ms against the default set's 1.3 ms. **Taken with default features off and `syntect-onig` on.** The feature is a `#[cfg]` over *which dump is embedded*. With it off, the crate embeds the fancy-regex dump, which selects syntect's `regex-fancy` and compiles a second regex engine beside `onig`. Adding the crate locked exactly one package, but the lockfile is the weaker check: it already lists `fancy-regex` whether or not a feature selects it, so a future bump could pass there and still compile two engines. The reliable check is `cargo tree -i syntect -e features`, which must print `regex-onig` and no `regex-fancy`. Its grammars are also better than the defaults. `Vec` as a type, a JavaScript object property and Go's malformed `09` all started classifying correctly after the swap, with no change to `scope_kind` |
| File watching | `notify`, `notify-debouncer-full` | Debouncing matters, because an AI writing a file fires several events |
| Git | `git2` | `Repository::statuses()` gives exactly F7's rule: uncommitted against HEAD, untracked included, ignored excluded. For the diff itself, use `diff_tree_to_workdir_with_index` against HEAD, **not** `diff_index_to_workdir`. The latter misses staged changes, and misses untracked files entirely unless `include_untracked` and `show_untracked_content` are set, so a file the AI just created would appear in the review with an empty diff. A Story's range is the one diff that is *not* against the working tree. `main...HEAD` names two commits: the merge-base and the head. Varde resolves the merge-base with `merge_base`, so a base that moved on after the head forked does not look like a deletion. `diff_tree_to_tree` makes the hunks the range's own. Diffing the working tree over a fully committed range finds nothing, and the Remainder would report full coverage of nothing. Every path uses the same pinned `context_lines`. The untracked options have no effect on the tree-to-tree diff |
| Version comparison | `semver` | The update check compares the checkout's Version with the Running version. Do **not** hand-roll it: as strings, `"0.10.0" < "0.9.0"`, so a byte-wise compare calls the newer checkout older and the Update never appears. It was already in the lockfile as a transitive dependency, so making it direct downloads nothing |
| Checksums | `sha2` | F39's R39.4: Varde verifies a downloaded Asset against the Release's `SHA256SUMS` before it replaces the running binary. Small, pure Rust, one call, and it keeps the verification in the library under a unit test. Shelling out would mean `shasum` on macOS and `sha256sum` on Linux, a platform branch for a solved problem |
| Shell quoting | `shlex` | R3.5. Do **not** hand-roll quoting; see the note below |
| Gitignore matching | `ignore` | The crate behind ripgrep. R2.3 (dim ignored paths) and R7.2 (exclude them from review) both depend on ignore semantics, which are much subtler than they look |
| Find in files | `grep-searcher`, `grep-regex` | ripgrep's own engine as crates. Find runs on the `ignore` crate's parallel walker and searches each file without reading the project into memory, skipping binary files the way ripgrep does. The regex is built from the query as a fixed string with smart case, and `search::occurrences` still decides each line's hit and column, so the matching rule did not change when the engine did (#109) |
| Layered config | `figment` (or `serde` + `toml` directly) | R9.4 is global → project → defaults precedence, which is what figment does. Evaluate it before hand-writing a deep merge |
| Config | `serde` + `toml` | F9's `config.toml` |
| Editing the global config | `toml_edit` | ADR 0018: taking a Tools row appends the template's row (and any `[facts.*]` row it names) to `~/.varde/config.toml`. `toml` reads a file into values and writes values back, which would drop every comment and any alignment the reader wrote by hand. `toml_edit` keeps a document's text, so Varde cuts the row out of the template whole, with the comment above it and its sub-tables. `Item::to_string` leaves the sub-tables out, which is why Varde renders the row as a document. Varde never reparses and rewrites the reader's text; it appends the rendered rows after the file's last byte. Same `toml-rs` family as `toml`, sharing its `toml_parser`, so it locked one package |
| State | `serde` + `serde_json` | F9's `state.json` |
| Text wrapping | `textwrap` | Varde sizes an overlay to its longest line and then clamps it to the screen, so a long `why` or Nudge used to be drawn clipped, with the end of the sentence missing. Varde now wraps the lines before measuring the box, not with `Paragraph::wrap`. The box's height comes from the line count, and a paragraph that wraps at render time makes that count wrong. Do **not** hand-roll it: word breaking, an over-long word with nowhere to break, and Unicode width are each a solved problem. It was already in the lockfile behind `clap`, so making it direct downloads nothing, the same reason `semver` is direct |
| Markdown parsing | `pulldown-cmark` | F26's Preview. The CommonMark pull parser that everything in Rust builds on, with no dependencies of its own to speak of. It emits events, not HTML, so the layout can stay a pure function in `src/preview.rs` that returns rows rather than a string someone has to re-parse. GFM is opt-in per flag (`ENABLE_TABLES`, `ENABLE_STRIKETHROUGH`, `ENABLE_TASKLISTS`). `ENABLE_YAML_STYLE_METADATA_BLOCKS` is why frontmatter arrives as its own event instead of rendering as a horizontal rule followed by stray text. Taken with `default-features = false`, because the defaults pull in an HTML renderer and `getopts` for a binary Varde never builds, and Varde wants events, not HTML. Brings `unicase` |
| Mermaid diagrams | `mermaid-text` | F26's R26.6. `render_with_width(src, Some(cols)) -> Result<String, Error>` turns text into text within a column budget. There is no browser, no `mmdc` subprocess and no Kitty or sixel image protocol, so a diagram's layout runs under a unit test like everything else rather than becoming an `Effect` the edge executes. `mermaid-svg` and `mermaid-rs-renderer` cover more diagram types but emit SVG, which is useless in a cell grid. **To be clear: this is a niche 0.x crate from one author, and it brings `ascii-dag`, `unicode-width` and `chrono`.** We took it anyway, because the alternative to a crate here is a graph layout engine, exactly the "looks small, and is wrong in ways no scenario covers" code AGENTS.md forbids. Without it, R26.6's error path is all that remains, so removing it means deleting one call. `render_with_width` never actually returns `Error::TooWide`, because that variant needs `RenderOptions::max_width_strict`, which the plain function does not expose. So `src/preview.rs` decides "too wide for the pane" afterwards, rather than reading it from the crate |
| Display width | `unicode-width` | `render_with_width`'s own compaction pass measures in display columns, so the too-wide check after it has to as well. `str::chars().count()` undercounts a wide character (CJK text in a node label) and would pass a diagram that is still too wide for the pane without saying so, or refuse one that fit. It was already in the lockfile behind `mermaid-text` and `ratatui`, so making it direct downloads nothing, the same reason `semver` is direct |
| Civil dates | `chrono` | F40's Authorship. A commit's timestamp is seconds since the epoch plus its author's UTC offset, and the border shows a date. Converting it is calendar arithmetic: leap years, leap-year exceptions and the days a timezone shifted. That is the "looks small, and is wrong in ways no scenario covers" code AGENTS.md forbids hand-rolling. Varde uses only `DateTime::from_timestamp` and `FixedOffset`, in `short_date` in `src/main.rs` and nowhere else. The core carries only the formatted string the edge gives it. Taken with `default-features = false` and only `std`, with no `clock`, because the only instant that matters is the one git recorded, not the system clock. It was already in the lockfile behind `mermaid-text`, so making it direct downloads nothing, the same reason `unicode-width` and `semver` are direct |
| Code metrics | `rust-code-analysis` | F27's Risk. Mozilla's tree-sitter-based analyser, pinned to the published **0.0.25**. A git dependency was rejected. The release is old and has older grammars, so some files come back Unparsed, and Varde shows those rather than hiding them. We accept that rather than depend on an unversioned moving target. It gives per-space metrics with names and start lines for the six languages that implement cyclomatic and cognitive complexity (Python, Rust, C/C++, Java, JavaScript, TypeScript/TSX), so Varde shells out to no other analyser and hand-rolls no metric. The pin brings two constraints. **Its types reach `src/main.rs` and nowhere else.** A `0.0.x` release may break its API on any upgrade, so `src/risk.rs` defines Varde's own `Space`/`Metrics` and the edge converts field by field. Grep `rust_code_analysis` and every hit is in the edge. And **`tree-sitter` is held at 0.20.9 in `Cargo.lock`**. `tree-sitter-rust` 0.20.3 asks for `>=0.20`, and resolving that to 0.27 gives two incompatible `Language` types and a compile error inside the analyser's own macro. If a `cargo update` breaks the build here, that is why, and `cargo update tree-sitter@<new> --precise 0.20.10` fixes it |
| Run marks | `tree-sitter` + `tree-sitter-{rust,java,javascript,typescript,python}` | F41. This is the structural feature the `syntect` row said tree-sitter was waiting for. A `[run.*]` row finds what can be started with a tree-sitter **query**, which is data, so no code names a `main` or a test. **Taken at exactly the versions `rust-code-analysis` already locked** (tree-sitter 0.20.9 and those five grammars), so adding them compiled nothing new and locked no package. A second tree-sitter runtime is not an option, because both would link the same `ts_*` C symbols. The grammar table in `src/run.rs` is the one place an extension is mapped to a parser, and it covers only that set. Varde refuses a row for a language outside it at start, as `no grammar parses .<ext>`, rather than treating it as configured. Loading grammars from shared libraries would remove that limit, and was left out: it would be native code named by configuration, and a project config, from the opened folder, could supply it |
| LSP wire types | `lsp-types` | F31. The protocol's request, notification and reply shapes as `serde` structs. They are pure data with no I/O, which is why they may enter the library at all: `src/lsp.rs` builds every outgoing message from them and the edge decides nothing. Taken at **0.94** rather than 0.97 for `Url::from_file_path`. 0.97 replaced `url::Url` with `fluent-uri`'s `Uri`, which has no path constructor, and building a `file://` URI by hand means percent-encoding. That is a solved problem, and a hand-rolled version breaks on the first path with a space in it. Brings `url` |
| LSP framing | `lsp-server` | F31. `Content-Length` framing over a child's stdio: `Message::read` from a `BufRead` and `Message::write` to a `Write`. It is rust-analyzer's own crate, **synchronous, with no async runtime**, which is why it was chosen over `tower-lsp` or `async-lsp`: `tokio` is a dev-dependency here and must stay one. Do **not** hand-roll the framing. A slightly wrong header parser desynchronises the stream, and every message after that is garbage. `src/rpc.rs` is the only file that names it, the way `pty.rs` is the only file that names `portable-pty` |
| DAP messages and framing | none; `serde_json` and `src/rpc.rs` | F45, ADR 0021. **No crate, on purpose, after looking.** `dap` (0.4.1-alpha, 2023) is written for implementing an adapter: its requests only deserialize and its responses and events only serialize, the opposite of what a client needs. `dap-types` is a 0.0.1 stub. So `src/debug.rs` builds requests with `serde_json::json!` and reads replies and events from `serde_json::Value`. The protocol's shapes are JSON the core decides about, and reading the few fields Varde uses from a `Value` is less code than a type per message. The framing is LSP's `Content-Length` header, but `lsp-server` cannot be reused, because its `Message` requires a `jsonrpc` field DAP does not have. `rpc::read_frame` is the one hand-rolled parser, with a unit test for the two ways it can go wrong: a length counted in characters rather than bytes, and a header it does not know |
| Finding a command | `which` | F31's R31.23: whether a configured server command is on this machine, checked at the edge when the palette's server list opens. `which::which(command)` handles a bare name on `PATH`, an absolute path and Windows' `PATHEXT`. A hand-rolled `PATH` split gets those three wrong in ways nobody notices, starting with the executable bit. Named only in `src/main.rs`: the answer reaches the core as `State::commands_on_path`, which `update` reads and never writes. One small crate, and it locked **no new package at all** on this platform, because its only dependency is `libc`, which was already in the tree |
| Process liveness | `libc` | On start, the Sidecar sweep (ADR 0016) deletes every `~/.varde/paths/` directory whose Varde has exited, and Varde checks that with `kill(pid, 0)`, which delivers no signal and only asks. `libc` was already in the tree under `which`, so it costs nothing. The alternative was running `kill -0` per directory, which spawns a process to ask what the syscall answers, and reads `EPERM` as the process having exited. Named only in `src/main.rs`, in `alive`, which is the one `unsafe` block in Varde. `EPERM` counts as alive, because the one mistake this check must avoid is deleting the Sidecar of a running instance. **Unix-only, and the first Unix-only thing in the tree.** `kill` has no Windows equivalent, so a port needs its own answer here. Varde already drives a pty and reads `stty`, so this is not where portability is lost |
| Sentence boundaries | `unicode-segmentation` | F35's R35.4. An Utterance is a sentence, and where a sentence ends is defined by UAX #29, not by `[.!?]`. This repo's prose uses `1.0`, `R3.3`, `e.g.` and colons constantly, and a hand-rolled split makes "It goes to 1." one Utterance and "An IDE TUI:" another. The prototype produced exactly those. `unicode_sentences()` also drops a fragment with no content, so an empty piece never reaches the voice. Named only in `src/reading.rs`, in one pure function under unit test. It was already in the lockfile behind `textwrap`, `syntect` and `mermaid-text`, so making it direct downloads nothing, the same reason `unicode-width` and `semver` are direct |
| WAV container | `hound` | F35's R35.4 at the edge. A Reading is one continuous stream, so Varde joins the synthesizer's per-Utterance files and the silence between them into a single wav before spawning a player. A player per Utterance was rejected after listening to it. The container is where hand-rolling is expensive. A RIFF header stores the length in two places, and a hand-patched header is wrong in a way nothing in Varde would notice until a player refused the file, on a path **no test covers by design**. `hound` reads and writes 16-bit PCM with **no dependencies of its own**, one locked package, and is named only in `src/main.rs`, in `stitch`, the way `portable-pty` is named only in `pty.rs`. `symphonia` and `rodio` decode and play far more, which means a decoder and an audio device Varde deliberately does not own: the player is a `[speech]` row, per ADR 0013 |
| Finding URLs | `linkify` | R10.9: the URL under a jump-modifier click on a pty's row. Do **not** hand-roll it, because the hard part is where a URL *ends*. A sentence's trailing full stop is not part of it. A `)` closing a `(` inside a Wikipedia path is. A `)` closing the parenthesis the URL was written in is not. `linkify` handles exactly those, and a split on whitespace gets every one wrong. Named only in `src/editor.rs`, in `link_at`, which also refuses every scheme except `http` and `https`, because the crate finds any scheme and the operating system's opener would launch whatever a child printed. One package, and it brings only `memchr`, already in the tree |
| CLI args | `clap` | The workspace path argument, F1 |
| Errors | `thiserror` (lib), `anyhow` (bin) | Typed errors in `src/`, context at the edge |
| BDD tests | `cucumber` (cucumber-rs) | Runs the existing `features/*.feature` unchanged |
| Unit tests | built-in `#[cfg(test)]` | No dependency needed |
| Fixture directories | `tempfile` (dev only) | R31.27's edge resolution answers a question about a directory layout. A `typescript/lib` holding `typescript.js` is an SDK, and one holding only `tsc.js` is the 7.0 native preview, installed and useless. So the test that pins the difference needs real directories. It is a **dev-dependency**, and the only place a test touches a filesystem. `main.rs`'s edge tests ask it the same questions the edge asks, and nothing in `src/` reads one. `tempfile::tempdir()` cleans up on drop, including after a test panics, which a hand-rolled name under `std::env::temp_dir()` gets wrong |

## Where the spec pins the stack

Several crates follow from decisions the spec already made. They are not free choices:

- **`crossterm`'s keyboard enhancement flags** are the only way to detect F6's `Ctrl+Ctrl`. The Kitty
  keyboard protocol reports a bare modifier keypress. Pushing those flags implements R6.1, and the
  terminals that reject them are exactly the ones that fall back to `Ctrl+Space`.
- **`git2`'s status API** matches R7.1 and R7.2 directly: uncommitted against HEAD, untracked
  included, ignored excluded. Any other choice means reimplementing ignore semantics.
- **`notify` with debouncing** serves F5. Without debouncing, a single AI write can fire
  create+modify and produce two reload prompts.
- **`rust-code-analysis`'s parent-space metrics are inclusive**, which is what makes F27's "a closure
  counts toward the Function holding it" actually hold. The `*_sum()` getters include every child
  space's contribution, so the conversion reads those, and the Function rule stops descending at the
  first function it meets. That was an assumption until a fixture test in `src/main.rs` confirmed
  it. That test fails if a future release makes subspace metrics exclusive.
- **`vt100` + `portable-pty`** make F3 and R10.5 work. The injected command goes into a terminal
  model Varde owns, and `mouse_protocol_mode()` answers whether the child wants the click.

## Quoting: `shlex` matches the spec

Checked against `shlex` 2.0.1: its output is exactly what the F3 Outline specifies, including the
apostrophe row:

```
/home/me/projects/varde/src              (bare)
'/home/me/projects/varde/my notes'       (single-quoted)
"/home/me/projects/varde/don't"          (double-quoted)
'/home/me/projects/varde/a;b'            (single-quoted)
```

shlex picks the quoting style per input rather than always single-quoting, which is why it agrees
with the spec. It also handles Q34, a path containing both quote characters:
`/tmp/don't"quote.txt` becomes `"/tmp/don't\"quote.txt"`.

Do not hand-roll quoting, and do not unit-test shlex's output, since that tests someone else's code.
The F3 Outline is the contract, and it passes as written.

## Highlighting: scopes, not colours

`syntect` returns Sublime scopes, over the 220-grammar set `two-face` supplies. Know these three
things before changing `src/highlight.rs`:

- `fn`, `let` and `const` come back as **`storage.type`**, not `keyword.*`. They are keywords to a
  reader, so the classifier treats `storage` as a keyword. Testing for `keyword` alone finds nothing.
- A quoted string arrives in three pieces (the opening quote, the text, the closing quote), because
  the quotes also have `punctuation.definition.string`. The highlighter merges adjacent tokens of the
  same kind, so a string arrives whole.
- Varde looks up a grammar by extension first and by *name* second, because a fenced code block in
  the Markdown preview has no filename, only its info string. Both lookups use the same set. A
  language neither finds comes back as one plain token rather than failing.

Scenarios assert the *kind* a piece of text has, never its colour. Colour lives in `src/ui.rs` and
comes from `editor.theme` through the F9 config layering.

## Testing shape

- Behaviour: `features/*.feature`, run by `cargo test --test cucumber`. Step definitions live in
  `tests/` and call into `src/`.
- Units: `#[cfg(test)] mod tests` beside the code they cover.
- The clock is injected, never real. F6 specifies a 300 ms double-tap window and a 450 ms non-tap,
  and neither should cost wall-clock time in the suite.
- Nothing in the suite spawns a real pty or scrapes ANSI. See AGENTS.md.
